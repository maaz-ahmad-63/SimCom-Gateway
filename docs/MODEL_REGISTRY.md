# AI model registry (the Model Hub)

Providers and models are configuration, not code. The gateway reads **one provider list and one flat model list** from `registry.json`; the
dashboard's **AI → Model Hub** tab edits it through `/api/ai/registry`. Prices are a separate, optional file. Only a genuinely new API
protocol needs code.

## The three ideas

| | What it is | Where it lives |
|---|---|---|
| **Protocol** | A wire format the gateway can speak (`openai-chat`, `inworld-tts`, `deepgram-listen` ...). Described once: its stage, its settings, its default endpoint, what it can do, a read-only key check and how to build the client. | `src/ai/registry/protocols.ts` (code) |
| **Provider** | A credential (the **name** of the variable that holds the key) and, for OpenAI-compatible services, a base URL. | `registry.json` → `providers` |
| **Model** | One entry per model: its provider, protocol, the provider's model id, optional endpoint, and the protocol's own settings under `options`. | `registry.json` → `models` |

## Files

| File | Holds |
|---|---|
| `<database folder>/registry/registry.json` (`AI_REGISTRY_DIR` overrides the folder) | `{ "schemaVersion": 2, "providers": [...], "models": [...] }` — the whole list |
| `registry/pricing.json` | `{ "schemaVersion": 2, "prices": [...], "sources": [...] }` — optional |
| `registry/pricing-state.json` | price proposals, source checks, price history |
| `registry/.last-valid/` | the last good copy of each file, used if a file is damaged before the next start |

Until something is changed **nothing is written**: the registry is the built-in defaults (the original `catalog.ts`, generated by
`registry/defaults.ts` with the same ids, aliases and parameters). The first change writes the whole list. The file is then the list: edit it
by hand or through the Hub. Defaults that are missing (for example models a newer gateway ships) are added back with **Add missing defaults**;
a changed default is put back with **Reset to default**. Default entries are never deleted, only switched off.

## Schema (strict: an unknown field, wrong type or out-of-range value is an error)

**Provider** `{ id, name, credential, baseUrl?, enabled?, note? }`
* `credential` is the **name** of an environment variable or stored credential, ending `_API_KEY` or `_API_TOKEN` (`GROQ_API_KEY`). The key is
  read from the encrypted store first, then the environment (the existing `.env` keys). The registry never holds a key, and anything that
  looks like one is rejected.
* `baseUrl` is the base of an OpenAI-compatible API (https, never a local/private address; the key is sent there). It applies to models that use a
  protocol whose endpoint is a *base* (`openai-chat`, `elevenlabs-tts`). Other protocols use their own address, or the model's `endpoint`.

**Model** `{ id, stage, provider, protocol, model, label, enabled?, aliases?, endpoint?, options?, unavailableReason? }`
* `stage`: `llm`, `stt` or `tts`. Ids are unique per stage (`soniox` exists as both a speech-to-text and a text-to-speech model).
* `protocol`: one of the protocol ids; `null` lists a model nothing implements yet (it must say why in `unavailableReason`).
* `model`: the provider's own model id, sent as written. For text-to-speech it is the default model.
* `endpoint`: overrides where this model connects (the whole URL; the base URL for `openai-chat`; `wss://` for the WebSocket protocols).
* `options` are the protocol's own settings, validated strictly by that protocol:
  * `openai-chat`: `body` (fixed request fields; a value may be `{ "$env": "NAME", "default": …, "oneOf": […] }` to be overridable from the
    environment), `reasoningTokenAllowance`, `tools` (function calling; default true, false for Telnyx until verified), `family` (call-log label).
  * `deepgram-listen`: `language: "multi"` for the multilingual mode. Other speech-to-text protocols take no options.
  * text-to-speech: `voice` (default), `sampleRates` (the raw PCM rates the provider documents; the gateway rate must be one of them), `voices`
    (`[{ name, id?, label? }]`: named voices, and name → id for providers whose voices are ids), `models` (more model ids that can be chosen).
    `deepgram-tts` has no `models`: its voice selects the model.

What a protocol can do (streaming, batch, function calling, structured output, voice selection, languages, cancellation) is stated by the
gateway's code and shown in the Hub. A JSON entry cannot claim more.

## Add a model to an existing provider (configuration only)

Model Hub → the stage's tab → **Add model**, or add an entry to `models` in `registry.json`:

```json
{ "id": "groq_llama_4_scout", "stage": "llm", "provider": "groq", "protocol": "openai-chat",
  "model": "meta-llama/llama-4-scout-17b-16e-instruct", "label": "Groq Llama 4 Scout", "options": { "body": { "temperature": 0.5 } } }
```
```json
{ "id": "inworld_max", "stage": "tts", "provider": "inworld", "protocol": "inworld-tts", "model": "inworld-tts-1.5-max", "label": "Inworld Max",
  "options": { "voice": "Sarah", "sampleRates": [8000, 16000], "voices": [{ "name": "Dennis" }] } }
```

**Test** it (read-only: lists the provider's models with your key; nothing is generated) and **Use for new calls**. The three stages have
independent defaults (the existing `AI_LLM`, `AI_STT`, `AI_TTS` settings) and a change applies to the next call.

## Add a provider

* **An OpenAI-compatible service** (chat completions, server-sent events): configuration only. Add a provider with its `credential` name and
  `baseUrl`, store the key under **API Keys** (or put the variable in the environment), then add models with `protocol: "openai-chat"`.
* **Another API that an existing protocol speaks** (a second Deepgram or Inworld account, a regional endpoint): add a provider with its own
  credential name and give its models an `endpoint`.
* **A different wire format**: this needs code, because JSON cannot implement a protocol. Write the client class in `src/ai/providers/` (the
  existing ones are the pattern: honour the abort signal and the PCM format), then add **one entry** to `PROTOCOLS` in
  `registry/protocols.ts` with its id, stage, options schema, default endpoint, facts, probe and `create`. Nothing else lists protocols: the
  Hub, validation, provider construction and key checks all read that entry.

A provider or model is described as supported only when its protocol exists **and** it has been tested. A model added through the Hub has been
validated structurally and by the read-only test; it has not made a real call.

## Credentials

Providers name variables; they never hold values. The encrypted store (`AI_SECRETS_MASTER_KEY`) accepts the built-in credential names plus the
name of any provider in the registry, and nothing else. A stored key beats the environment. A missing key is reported by name only. Existing
`.env` keys keep working unchanged.

## Pricing (separate and optional)

A model needs no price. With none, its price is unknown (`null`), its cost estimate is unknown, and nothing else changes; a damaged
`pricing.json` never affects which models run, and the reverse. Every price carries currency, billing unit, plan, source URL, verification date,
effective date and status; `imported-unverified` marks the figures that came with the original catalog.

* **Sources** (`pricing.json` → `sources`): official pricing pages (OpenAI, Groq, Google Gemini, Telnyx, Deepgram, Soniox, Inworld, Cartesia to
  start). They are pages for people, so nothing is extracted from them. **Check sources** (a button, never a call or a timer) records when each was
  fetched and a hash of its text, says whether it changed, reports a refusal (HTTP 403) or a redirect (not followed), and refuses local/private
  addresses. Checked 2026-10-30: OpenAI's page is `developers.openai.com/api/docs/pricing`; Groq's `/pricing` redirected to its home page, so that
  URL is marked unconfirmed.
* **Proposals**: reviewed prices are pasted as JSON and become a proposal showing new / changed / unchanged and what is held back. Nothing is
  active until approved. A negotiated, hand-entered or `protected` price is never replaced unless the approver names it, and a change that would
  turn a known price into an unknown one is held back the same way. A price edited after the proposal is skipped as stale. Replaced prices are kept
  in history.

## API (under `/api/ai/registry`, API key required)

`GET /` · `GET /export` · `POST /validate` · `POST /import` (`dryRun`) · `POST /restore-defaults` · `POST|PATCH|DELETE /providers[/:id]` ·
`POST /models` · `PATCH|DELETE /models/:stage/:id` · `POST /test/provider/:id` · `POST /test/model/:stage/:id` · `POST /pricing/check` ·
`POST /pricing/proposals` · `GET /pricing/proposals/:id` · `POST /pricing/proposals/:id/approve|reject` · `GET /pricing/history`.
A rejected change answers 422 with every issue and changes nothing. No response contains a credential value.

## Safety rules

Every change is validated as a whole before anything is written; only a valid registry is installed. A damaged file leaves the last valid registry
in force and is reported. A change that would disable or delete the model, voice or default of a stage that is in use is refused. The registry is
read when a call's providers are built; a call in progress keeps the providers it started with.
